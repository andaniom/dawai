## Project Overview

**DAWAI** — Sistem Penilaian Biola Berbasis Web, Multi-Tenant. Violin assessment platform serving multiple schools on a single shared-database architecture. See PRD-Aplikasi-Penilaian-Biola.md for complete specification.

**Architecture:** Decoupled Go API (Fiber, port 8080) + Next.js frontend (port 3000) + PostgreSQL + MinIO.

**Multi-tenant model:** Shared database with school-level isolation via `school_id` application-layer guards. No PostgreSQL RLS.

### Database Schema

All schema in PostgreSQL. Tenants isolated via `school_id` column in every table. See PRD section 10 for full DDL.

Key tables:
- `schools` — tenant root
- `users` — all people (school_id, email, password_hash); role no longer a column
- `roles` — lookup: super_admin, school_admin, teacher, student, parent
- `user_roles` — many-to-many junction; 1 user can hold multiple roles
- `students` — student records (linked to users via user_id, nullable)
- `assessments` — score records per song/session
- `assessment_components` — rubric component scores (part of single assessment)
- `rubric_components` — rubric definition per school
- `songs` — song library per school
- `audit_logs` — write operation trail

Indexes on: `school_id`, common filter columns, FK references. See PRD section 10.3.

## Key Development Patterns

### Multi-Tenant Isolation (CRITICAL)

**Rule:** `school_id` MUST be extracted from JWT claims via `c.Locals("school_id")` in Go. Never from request body, query params, or URL path (except super_admin using `x-school-id` header).

```go
// ✅ CORRECT
func GetStudents(c *fiber.Ctx) error {
    schoolID := c.Locals("school_id").(string)
    rows, err := db.Query(ctx,
        `SELECT id, name FROM students WHERE school_id = $1`,
        schoolID,
    )
    // ...
}

// ❌ WRONG (security bug)
func GetStudents(c *fiber.Ctx) error {
    rows, err := db.Query(ctx, `SELECT * FROM students`)
    // ...
}
```

**Cross-tenant validation:** When referencing entities (e.g., `student_id` in assessment), always verify the entity's `school_id` matches request context:

```go
var studentSchoolID string
err := db.QueryRow(ctx,
    `SELECT school_id FROM students WHERE id = $1`,
    body.StudentID,
).Scan(&studentSchoolID)

if err != nil || studentSchoolID != c.Locals("school_id").(string) {
    return fiber.NewError(fiber.StatusForbidden, "Student not found in your school")
}
```

### JWT Auth Flow

1. NextAuth (Next.js) handles Google OAuth + email/password credentials
2. After credential verify, NextAuth calls `POST /api/auth/token` (Go) with credentials
3. Go validates, issues JWT with `school_id` + `roles` (array, joined from `user_roles`) in claims
4. JWT stored in NextAuth session (httpOnly cookie)
5. NextAuth injects JWT into `Authorization` header on all Go API calls
6. Go middleware (`JWTGuard`, `TenantGuard`, `RoleGuard`) validates token + injects `school_id`/`roles` into `c.Locals()`; `RoleGuard` checks endpoint's required role is present in the roles slice

**Token blacklist on logout:** POST `/api/auth/logout` blacklists JWT `jti` in PostgreSQL `jwt_blacklist` table.

### Database Migrations

All schema changes via **golang-migrate** SQL files in `backend/migrations/`.

```bash
cd backend

# Create new migration
migrate create -ext sql -dir migrations -seq create_new_table

# Edit migrations/000XXX_create_new_table.up.sql and .down.sql
# Migrations run automatically on docker compose up
```

Never use Prisma — migrations are raw SQL only.

### API Patterns

- **Super admin endpoints:** `/api/super-admin/*` — admin-only, take `school_id` from `x-school-id` header
- **Tenant endpoints:** `/api/*` — school_id from JWT, no URL path component for it
- **No API routes in Next.js** — all endpoints in Go
- **Offline support:** POST `/api/assessments` accepts `idempotency_key` UUID; resubmit returns 409 with existing ID

### i18n (next-intl)

- Locales: `en` (default), `id`
- URL strategy: path prefix (`/en/*`, `/id/*`)
- Translations: `frontend/messages/en.json` and `frontend/messages/id.json`
- User preference stored in `users.preferred_locale` (set after login)
- Auto-generated descriptions (KurMer reports) always output Indonesian

### Role-Based Access Control

| Role | Scope | Permissions |
|---|---|---|
| `super_admin` | Platform | Create/manage schools; impersonate schools via `x-school-id` |
| `school_admin` | 1 school | Manage users, rubric, songs, assessments |
| `teacher` | 1 school | Submit/edit assessments, view students |
| `student` | Self only | Read own data + assessments |
| `parent` | 1 child | Read child's data via `parent_students` relationship |

Enforcement: `RoleGuard` middleware checks JWT `roles` claim (array) against endpoint requirements — a user matches if any of their roles satisfies the route.

## Important Notes

### Tenant Isolation is Non-Negotiable

Every query touching a tenant table MUST filter by `school_id`. Code review must verify this in every handler. Missing a single filter is a data leak.

### Password Hashing

- Use bcrypt (cost ≥ 12) for all user passwords
- Library: `golang.org/x/crypto/bcrypt`

### Audit Logging

Write operations (INSERT, UPDATE, DELETE on tenant data) must log to `audit_logs`:

```go
// Log user created a student
err := auditLog(ctx, schoolID, userID, "create_student", "students", studentID, nil, newData)
```

### Rate Limiting

Auth endpoints (login, forgot-password, reset-password) limited to 10 req/min per IP.

### HTTPS

All production endpoints must be HTTPS. Docker compose runs unencrypted locally.
